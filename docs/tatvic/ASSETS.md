# ASSETS.md — Tatvic context and what a good opportunity looks like

> Product intent: [`MASTER_SPECIFICATION.md`](../../MASTER_SPECIFICATION.md). India-first delivery context; offerings below are leverage anchors.

## 1. What Tatvic delivers

Tatvic offers services only in these domains:
- AI and ML
- Data science
- Cloud and data engineering
- Data analytics
- GA and Tag Manager implementation
- CRO (conversion rate optimisation)
- Agentic AI (the form in which most new offerings are delivered)

A problem is relevant only if it sits inside these domains. Anything else is out of scope. Capacity and team size are not scored here. Effort is scored only with the anchors in RUBRIC.md.

## 2. Existing offerings used as worked examples

These are NOT things to improve by default. They show how a real problem was found and turned into a solution. Use them as examples of a good problem-to-solution fit, and as the reference for the Leverage score in RUBRIC.md.

### Example A: BQ Agent
- Problem found: Non-technical people find it hard to query data and get insights. Every question needed someone to write SQL.
- Solution: An agent that turns plain-English questions into SQL, and answers simple questions without the user needing to see or write any SQL.
- Who it helps: Non-technical business users who need answers from BigQuery data.
- Known limit: It cannot handle advanced, complex queries.

### Example B: CRO Excalibur
- Problem found: Even a basic CRO or UX experiment took a lot of time to set up and run.
- Solution: An agent that runs a basic experiment in a few minutes, so people get a first taste of what CRO is.
- Who it helps: Teams that have never run a CRO experiment, or need a quick first one.
- Known limit: It is for initial experiments only. It does not replace intense, human-level testing.

### Example C: Agentic TimesFM
- Problem found: Getting a forecast meant sharing a full history of data with a third party.
- Solution: A site where the user enters their own past 180 days of data and gets a general forecast and insight, without handing over their whole dataset.
- Who it helps: Teams that want a quick, general forecast without a full data-sharing engagement.
- Known limit: It does not replace traditional forecasting where fine detail matters.

### Other existing offerings

These count as "existing offerings" when scoring Leverage and when choosing the offering angle.

## 3. The pattern of a good opportunity

All three examples share one pattern. A strong opportunity usually has most of these:
1. A task people do today that needs an expert, takes a long time, or requires sharing sensitive data.
2. A narrow first version that does the basic, common part of the task in minutes.
3. It is self-serve: a non-expert can use it without help.
4. It is honest about its limits. It is a starter or entry-level tool and does not claim to replace deep expert work.
5. It sits inside one of the domains in section 1.

## 4. How to use this file

- Match problems to the pattern in section 3, not to keywords in section 2.
- Leverage 4 or 5 is allowed only if the opportunity directly extends one of the offerings in section 2.
- Leverage 3: reuses parts of one offering. Leverage 1: unrelated to every offering.
- "New agent or offering" must still follow the pattern in section 3.
- "Cheaper delivery of an existing service" applies when Tatvic already sells the service and a capability or native function makes it cheaper or faster.
- Smallest first version: describe the basic, common version that works in minutes, like the three examples, and state its limits.
- First client type: use the role, company type or vertical that is evident in the source items. If none is evident, use the author's role as the client type. Never invent a client name.
- Never claim an offering does something not written in this file.
